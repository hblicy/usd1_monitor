# HTTP 重试状态诊断设计

## 目标

当 HTTP 请求因可重试响应状态耗尽重试次数时，最终错误应显示 HTTP 状态码以及已有的数字错误码，以便区分 Alchemy `429` 限流和 `5xx` 服务端错误。

## 范围

- 仅修改 `HttpRequestError` 对 `HttpResponseError` 原因的安全摘要。
- 保留现有重试次数、退避行为、异常类型和调用接口。
- 不记录响应正文、JSON-RPC 错误消息或未脱敏 URL，避免泄露 API Key。

## 行为

- 原因是 `HttpResponseError` 时，错误末尾显示 `HttpResponseError status=<状态码>`。
- 存在数字错误码时，继续显示 `code=<错误码>`。
- 其他异常仍只显示异常类型，保持当前行为。

## 测试

- 先添加回归测试，证明当前实现丢失状态码。
- 验证 `429` 状态和错误码被保留。
- 验证完整错误字符串不包含 URL 中的密钥或响应消息。
- 运行 HTTP/RPC 相关测试及完整测试集。
