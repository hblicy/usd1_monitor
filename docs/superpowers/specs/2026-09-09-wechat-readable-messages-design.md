# USD1 微信通知易读化设计

日期：2026-09-09
状态：用户已确认方案 1

## 目标

把企业微信通知从内部诊断日志改成普通用户能直接理解的中文消息。用户应能快速看懂风险等级、发生了什么、关键数值、时间、来源以及下一步建议。

## 硬性约束

- 企业微信请求继续使用 `msgtype=text`，不得改用 Markdown 消息类型。
- 消息正文只使用纯文本、换行、中文标签、Emoji 和完整 URL。
- 不使用 Markdown 标题、项目符号、加粗、代码、表格或链接语法。
- 不展示 `rule_id`、`cause_id`、哈希、事件键、函数选择器及其他内部字段名。
- 不改变风险判断、状态持久化、去重、恢复条件和发送重试逻辑。

## 消息结构

风险消息固定按以下顺序组织：

1. 第一行显示 Emoji、USD1 和中文状态：`🟢 正常`、`🟡 注意`、`🔴 危险`。
2. `发生了什么：`使用一句中文概括事件。
3. 仅在有帮助时显示关键数值和触发条件，字段名改为自然中文。
4. 显示北京时间，格式为 `YYYY-MM-DD HH:mm:ss`。
5. 显示一个或多个完整来源 URL；没有外部 URL 时不输出“未提供”。
6. 最后一行显示简短建议。注意或危险状态提示用户打开来源并人工确认；恢复状态提示继续观察。

同一次状态变更包含多个事件时，使用 `事件 1`、`事件 2` 分隔，每个事件保持上述结构；不得暴露内部分组 ID。

## 中文摘要映射

格式化层根据现有规则类别生成固定中文摘要，不引入 AI 或外部服务：

- 市场价格：说明 USD1 当前价格偏离 1 美元，并显示价格和阈值。
- 市场流动性：说明指定交易对流动性、点差或退出容量异常。
- 储备与供应：说明储备数据过期、储备覆盖不足或供应量对账异常。
- 链上合约：说明管理员、实现合约、权限调用、大额铸造或销毁等变化，并保留必要的链名、地址和金额。
- 官方公告：直接显示分类器已经提取的风险语句，并说明来源机构。
- 采集健康：说明哪个中文名称的数据源暂时不可用，并给出简短检查建议。
- 未识别的现有规则：使用“监控发现异常，请打开来源并人工确认”，不得退回显示内部规则编号。

底层证据继续完整保存在数据库和日志中，微信展示层只选择对用户有用的字段。

## 启动消息

启动消息改为纯中文摘要：

`🟢 USD1 监控已启动`

随后显示“正在监控”和“暂未覆盖”两部分。内部采集器名称转换为价格、流动性、链上合约、供应量、储备、官方公告等中文能力名称；不显示 `enabled_collectors`、`NOT_MONITORED` 或版本内部列表格式。

## 错误与长度处理

- 微信接口调用失败仍沿用现有可追溯错误和重试逻辑。
- 缺少可选证据时省略对应行，不拼出 `None`、空列表或“未提供”。
- 保留现有 2048 字节限制；拆分后的每一段仍为纯文本。
- 格式化器遇到未知规则时输出通用中文摘要，不吞掉该次通知。

## 验收测试

- 价格、官方公告、链上事件、健康异常和恢复消息均生成直白中文。
- 状态只显示 `🟢 正常`、`🟡 注意`、`🔴 危险`，不显示 GREEN、YELLOW、RED。
- 消息不包含内部规则编号、原因哈希、内部英文字段名或 Markdown 语法。
- 多来源 URL 逐行保留，时间转换为北京时间的易读格式。
- 启动消息不再显示采集器内部名称和未监控项内部标识。
- 企业微信 payload 保持 `msgtype=text`。
- 现有去重、恢复、分段、重试及完整离线测试继续通过。

## 不在本次范围

- 不修改风险阈值或告警等级。
- 不修改数据库结构。
- 不增加配置开关、Web 页面或 AI 摘要。
- 不改变企业微信机器人或 webhook 配置方式。
