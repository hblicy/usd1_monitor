# USD1 仪表盘审查修复与 PoR 新鲜度归类设计

## 1. 目标与范围

修复 PR #8 审查确认的仪表盘问题，并纠正 `por.age` 的风险语义。保留现有采集频率、60/120 分钟阈值、SQLite 表结构和 `por.age` 规则 ID；不增加新采集器、配置项或数据库迁移。

本次包含：

- 监控进程停止后，仪表盘不得继续显示监控健康为绿色。
- 多个页面并发读取时，仪表盘不得因共享 SQLite 事务返回 503。
- 储备覆盖率不显示正号，只有变化率显示正负号。
- “当前提醒”中的资产风险与数据/监控异常分组展示。
- `por.age` 归类为数据及时性异常，不再提升 USD1 资产风险等级。
- 企业微信明确说明更新延迟不等于储备不足，分钟数取整。
- Oracle 出现一条新的有效时间戳后解除 `por.age`；储备金额变化仍需两条稳定记录才能恢复。

## 2. 方案选择

### 方案 A：保留规则 ID，统一分类函数（采用）

新增一个共享的规则分类函数，把 `health.*` 和 `por.age` 归入监控健康，其余规则保持原业务归类。命令行状态、状态引擎、企业微信和仪表盘全部复用该函数。

优点是无需迁移现有 `risk_states`、历史告警和数据库；升级后下一轮即可使用新语义。缺点是 `por.age` 的名称没有 `health.` 前缀，但分类关系由显式函数维护。

### 方案 B：把规则改名为 `health.por_freshness`

命名更直观，但需要迁移旧风险状态、告警键和历史查询，兼容风险明显高于本次需求，不采用。

### 方案 C：只修改企业微信文案

改动最小，但命令行和仪表盘仍会把数据延迟计入资产风险，无法解决根因，不采用。

## 3. 状态语义与企业微信

共享分类函数将 `por.age` 视为监控健康项：

- `business_overall()` 排除 `por.age`。
- `health_overall()` 包含 `por.age`。
- `status` 和仪表盘使用同一分类，不再各自判断 `health.` 前缀。
- 状态引擎为 `por.age` 选择监控健康总体等级，但企业微信使用专用标题，不写成“USD1 危险”或笼统的“监控异常”。

未恢复时的企业微信正文为：

```text
🟡/🔴 USD1 储备数据更新延迟

发生了什么：官方储备数据已有约 N 分钟未更新
说明：这不代表储备不足，只表示目前无法获得最新储备信息。
```

恢复时明确显示“USD1 储备数据已恢复更新”。分钟数四舍五入为整数。原有来源链接和北京时间继续保留。

`por.age` 只判断最新 Oracle 时间是否重新进入阈值。一条新的、有效且新鲜的 Oracle bundle 足以恢复。`por.reserve_change` 的两条不同且稳定记录恢复规则保持不变。

## 4. 仪表盘数据与并发

`DashboardRepository` 为完整快照事务增加实例级 `asyncio.Lock`。一个仓库仍只维护一个只读连接，但并发请求按快照串行执行，确保 `BEGIN`/查询/`COMMIT` 不交错；取消或异常时必须回滚并释放锁。

仪表盘使用 `collector_health` 中最新的成功或失败时间作为监控活动时间。没有任何活动记录时保持 `UNKNOWN`；最后活动距当前时间达到现有关键健康阈值 900 秒时：

- 监控健康至少为 RED；
- 增加“监控数据已经停止更新”提醒；
- `generated_at` 仍表示网页快照生成时间，页面同时展示采集器真实时间，不把查询时间当成采集时间。

900 秒沿用现有 `evaluate_health()` 的关键数据源失联阈值，不增加新的配置项。

## 5. 前端展示

“当前提醒”保留一个外层面板，在其中按有内容的分组分别展示：

- 资产风险；
- 数据与监控异常。

两个分组都为空时显示统一的正常提示。估算储备覆盖率使用无符号百分比格式，例如 `100.01%`；24 小时供应量变化继续显示 `+1.2%` 或 `-1.2%`。

## 6. 错误处理与兼容性

- SQLite 继续以 URI `mode=ro` 和 `PRAGMA query_only=ON` 打开。
- 并发请求只排队，不创建额外连接、不写数据库。
- 预期 SQLite/数据解析错误继续转换为 503；取消等非预期异常回滚后向上传播。
- 不删除或改写现有 `por.age` 数据，升级前后的历史记录保持可读。
- 不改变 PoR 采集失败规则 `health.por`；RPC 获取失败与 Oracle 数据更新延迟仍是两个独立信号。

## 7. 验收测试

- 业务总体为 GREEN、`por.age` 为 RED 时，资产风险仍为 GREEN，监控健康为 RED。
- `por.age` 企业微信不包含“USD1 危险”，包含“约 129 分钟”和“不代表储备不足”。
- 一条新的新鲜 Oracle bundle 可让 `por.age` 恢复，储备变化恢复规则不变。
- 把快照时间推进 30 天时，仪表盘监控健康为 RED，并显示停止更新提醒。
- 10 个并发快照全部成功，数据库哈希不变。
- 覆盖率显示 `102.38%`，24 小时变化显示 `+5%`。
- 当前提醒按资产风险和数据/监控异常分组，手机端仍无横向溢出。
- 全量 pytest、语法编译和依赖检查通过。
