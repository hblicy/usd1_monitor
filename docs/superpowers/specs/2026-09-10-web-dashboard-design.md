# USD1 只读网页仪表盘设计

## 1. 目标

为现有 USD1 风险监控器增加一个仅供本人查看的网页仪表盘。首版重点是快速回答三个问题：USD1 本身是否有风险、监控系统是否正常、关键数据现在是多少。

仪表盘必须保持只读，不发起 RPC/HTTP 采集，不发送通知，不修改 SQLite，不影响现有监控进程。页面同时适配手机和电脑，每 30 秒刷新一次。

## 2. 已确认范围

首版包含：

- 单独展示“资产风险”和“监控健康”，避免把数据源故障误解为 USD1 风险。
- 展示当前非绿色风险项及其可读中文说明。
- 展示 Binance 价格与百万美元退出价格、PoR 储备、完整多链供应量、估算储备覆盖率和 24 小时供应量变化。
- 展示各采集器最近成功时间、连续失败次数和简化后的失败原因。
- 展示最近的告警/恢复、链上事件和官方公告。
- 提供数据生成时间、最近成功刷新时间和过期提示。

首版不包含：

- 历史走势图和任意时间范围查询。
- 日志浏览、SQLite 查询控制台、告警确认、服务重启或配置修改。
- 公网访问、用户体系、登录认证、HTTPS 和反向代理配置。
- 新的链上或外部数据采集。

## 3. 访问和部署

新增命令：

```bash
python -m usd1_monitor --config config.yaml dashboard
```

仪表盘作为独立进程运行，与 `run` 监控进程共享同一个 SQLite 文件。服务地址固定为 `127.0.0.1`，不得通过 YAML 改成公网地址。配置新增：

```yaml
dashboard:
  port: 8080
```

端口必须为 1024–65535，默认 8080，确保非 root 的 systemd 用户可以启动。刷新周期固定为 30 秒，不增加不必要的配置项。

用户通过 SSH 隧道访问：

```bash
ssh -L 8080:127.0.0.1:8080 ubuntu@服务器IP
```

然后在本机浏览器打开 `http://127.0.0.1:8080`。

新增独立 `usd1-dashboard.service` 示例。服务使用与监控器相同的 Linux 用户和配置文件，但只读取数据库。网页服务退出、重启或查询失败不得影响监控进程。

## 4. 架构

### 4.1 DashboardRepository

新增专用只读仓库，通过 SQLite URI `mode=ro` 打开 `database_path`，并设置 `PRAGMA query_only=ON`。它不复用 `Storage.open()`，因为后者会创建表和执行兼容迁移。

仓库在一个短读事务中生成完整快照，保证同一响应中的风险状态、健康状态和指标来自同一个读取时点。SQLite WAL 允许该读事务与监控写入并行。

数据库不存在、无法只读打开、必需表缺失或查询失败时抛出可识别的仪表盘数据错误，不创建新数据库，也不把错误解释为绿色。

### 4.2 DashboardService

复用现有 `aiohttp`，不增加 FastAPI、Node 或前端框架依赖。服务提供：

- `GET /`：响应仪表盘页面。
- `GET /assets/dashboard.css`：响应本地样式。
- `GET /assets/dashboard.js`：响应本地脚本。
- `GET /api/dashboard`：响应一次完整只读快照。
- `GET /healthz`：只表示网页进程可响应，不代表监控数据为绿色。

所有资源随项目部署，不使用 CDN、外部字体、分析脚本或第三方前端资源。

### 4.3 前端页面

页面使用原生 HTML、CSS 和少量 JavaScript。JavaScript 每 30 秒请求一次 `/api/dashboard`，并在页面重新可见时立即刷新。

刷新成功时原子替换页面数据；刷新失败时保留上一屏成功数据，在顶部显示“数据暂时无法读取，当前内容可能已过期”，并显示最后成功刷新时间。首次加载即失败时只显示不可用状态，不显示绿色占位值。

## 5. 数据组成

### 5.1 状态

- “资产风险”使用现有 `business_overall()` 语义，排除 `health.*`。
- “监控健康”使用现有 `health_overall()` 语义，只包含 `health.*`。
- 当前风险列表读取所有非绿色 `risk_states`，业务风险与健康异常分组显示。

`risk_states` 目前只保存等级和时间。首版不修改数据库结构：仓库按 `risk_states.changed_at = alert_deliveries.created_at` 读取该次状态变化已经生成的可读通知正文；找不到正文时使用规则 ID 到中文标签的显式映射作为降级展示，不解析或拼凑技术堆栈。

### 5.2 核心指标

从 `observations` 读取每个 metric/scope 的最新记录：

- `market.mid_price`：`USD1USDT`、`USD1USDC`。
- `market.sell_1000000_terminal_price`：两个交易对的百万美元退出价格和 `fully_fillable`。
- `por.reserves`：Ethereum PoR 储备。
- `supply.multichain_total`：六条原生链完整供应量。
- `supply.estimated_collateralization`：储备与完整多链供应量的估算覆盖率。
- `supply.bridged_total`、`bridge.locked_total`、`bridge.issuance_delta`：桥接核对摘要。

24 小时供应量变化由最新 `supply.multichain_total` 与不晚于“当前时间减 24 小时”的最近一条记录计算，并沿用现有规则，只接受距离该基准不超过 75 分钟的记录。结果不写回数据库。指标必须携带 `quality`、数据时间和采集时间；缺失值显示“暂无数据”，不得显示 0。

### 5.3 健康和最近事件

- `collector_health`：采集器名称、连续失败次数、最近成功/失败时间和清理后的错误摘要。
- `alert_deliveries`：最近的告警和恢复正文，合并同一通知的分片，显示发送状态。
- `chain_events`：最近链上事件，保留链、事件类型、区块和浏览器链接所需字段。
- `announcements`：最近官方公告，显示来源、标题、发布时间和原始链接。

所有列表都使用固定上限，首版不做分页和全文检索。

## 6. 页面布局

采用已确认的“风险优先”布局：

1. 顶部并列展示资产风险和监控健康，手机端上下排列。
2. 紧接着展示需要处理的当前风险；没有风险时显示明确的“当前未发现业务风险”。
3. 以两列/四列响应式卡片展示核心指标。
4. 展示数据源健康列表。
5. 底部展示最近告警、链上事件和官方公告。

颜色只用于辅助识别：绿色、黄色、红色同时配有文字，不把颜色作为唯一信息。页面使用中文短句、北京时间和适合手机点击的来源链接。

## 7. API 响应边界

`GET /api/dashboard` 返回稳定的 JSON 对象：

```json
{
  "generated_at": "2026-09-10T08:30:00+00:00",
  "business": {"level": "YELLOW", "items": []},
  "health": {"level": "GREEN", "collectors": []},
  "metrics": {},
  "recent": {"alerts": [], "chain_events": [], "announcements": []}
}
```

成功响应使用 `Cache-Control: no-store`。数据错误返回 HTTP 503 和固定结构：

```json
{
  "error": "dashboard_data_unavailable",
  "message": "监控数据暂时无法读取"
}
```

响应和日志不得包含环境变量、RPC 密钥、企业微信 webhook、SQLite 绝对路径或未经清理的 URL 查询参数。

## 8. 安全

- 网络监听地址在代码中固定为 `127.0.0.1`。
- 只允许 GET/HEAD；其他方法返回 405。
- 仪表盘数据库连接强制只读和 `query_only`。
- 设置 `Content-Security-Policy`、`X-Content-Type-Options`、`Referrer-Policy` 和禁止缓存响应头。
- 页面不渲染数据库中的 HTML；所有标题、正文和错误通过文本节点输出，避免公告内容触发脚本。
- 外部来源链接只允许已有 `http`/`https` URL，并使用安全的新窗口属性。

## 9. 测试与验收

自动测试覆盖：

- Dashboard 配置默认值、端口范围和严格字段校验。
- CLI 能启动 `dashboard`，且退出时关闭服务和数据库连接。
- 仓库只读打开现有数据库，不存在数据库时失败且不创建文件。
- 资产风险与监控健康分离，UNKNOWN 不被显示为 GREEN。
- 核心指标读取、缺失值、质量标签和 24 小时变化计算。
- 当前风险可读正文及找不到通知正文时的中文降级。
- 最近列表固定上限，敏感 URL 和错误信息被清理。
- API 成功、503、禁止缓存和安全响应头。
- HTML 不依赖外网资源，30 秒刷新并保留最后成功内容。
- 手机和电脑断点下的关键布局规则。
- 现有全量测试继续通过。

人工验收：

1. 监控 `run` 正常运行时启动 dashboard 服务，确认两者同时访问同一 WAL 数据库且互不阻塞。
2. 通过 SSH 隧道在电脑和手机宽度下打开页面。
3. 确认资产风险和监控健康独立显示，微信中的当前异常能在页面中找到。
4. 等待一次监控写入，确认页面最多 30 秒后更新。
5. 暂时停止 dashboard 服务，确认监控和企业微信通知不受影响。
